# 共享文件风险模型

## 低风险

典型文件：

- `README.md`
- `CHANGELOG.md`
- 追加式日报、记录、简单说明文档

策略：

- 可以并行追加。
- 指定一个人在集成阶段整理语气和重复内容。

## 中风险

典型文件：

- 共享工具函数。
- 共享文档页。
- 示例数据。
- 公共测试夹具。
- 多个模块都引用的配置模板。

策略：

- 指定唯一 owner。
- 其他任务只提出需求，不直接修改。
- 如果必须修改，先在计划里声明依赖顺序。

## 高风险

典型文件：

- Schema。
- 接口契约。
- IR 或 DSL 核心定义。
- 代码生成器。
- 生成输出。
- 数据库迁移。
- 包管理锁文件。
- Git submodule 指针。

策略：

- 不允许多个任务并行修改。
- 如果必须改，先做 `feat/shared-foundation`。
- 生成物由同一个集成任务统一更新。
- 子模块指针由集成人负责更新。

## 判断原则

- 目录独立不等于文件归属独立。
- 谁修改契约，谁必须说明下游影响。
- 谁更新生成器，谁负责更新生成物或明确交给集成分支统一生成。
- 如果一个文件被三个以上任务依赖，默认至少是中风险。
