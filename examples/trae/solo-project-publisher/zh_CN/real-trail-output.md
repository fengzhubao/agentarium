## 正文草稿

### 1、Skill简介

SOLO Project Publisher

这是一个帮助开发者把真实本地仓库工作流整理成社区帖子、项目报告或技术案例的 Skill。它会从文件、命令、截图、生成产物等证据出发，输出结构化、可复查、适合发布的内容。

### 2、使用场景

开发者在完成一个本地项目任务后，经常需要把过程整理成社区帖子、项目报告、Release 说明或阶段总结。但真实工作流里通常有很多零散信息：需求来源、仓库状态、关键文件、命令输出、测试结果、截图、风险和后续计划。

这个 Skill 的目标不是替用户泛泛写一篇宣传文，而是帮助 TRAE SOLO 从真实项目证据出发，整理出一篇可以发布、可以复查、可以讨论的项目案例。

适合场景：

- 参加社区活动，需要把本地项目过程整理成参赛帖。
- 完成一个功能后，需要写一篇有证据的技术分享。
- 维护脚本、配置、工具链时，需要把改动背景、验证方式和输出物讲清楚。
- 希望 TRAE SOLO 帮忙检查帖子里是否有不该公开的路径、Token、账号或内部信息。

### 3、创作过程

这个 Skill 把一次项目发布拆成五步：

1. 界定范围：确认目标项目、公开边界和读者对象。
2. 检查材料：读取仓库文档、改动文件和验证命令输出。
3. 整理证据：整理场景、过程、结果、证据和风险。
4. 起草帖子：按论坛帖子结构生成正文。
5. 发布前复查：检查敏感信息、证据完整性和可读性。

我刻意没有把它做成单纯的“帖子润色器”。它要求每个关键结论都尽量有文件、命令、截图或前后对比支撑，这样发布出来的内容更可信，也更方便读者复现和提问。

### 4、使用步骤

示例输入：

```text
请使用 SOLO Project Publisher，把 ai/Trae/solo-skill-contest 这个目录下的比赛准备工作整理成一篇 SOLO 技能创作赛参赛帖。注意不要泄露 ai/config 里的敏感配置。
```

TRAE SOLO 会执行的工作：

1. 读取比赛分析、选题和执行计划文档。
2. 检查目录里哪些内容适合公开展示。
3. 提取真实过程：从两个活动链接到本地文档、Skill 草稿、发帖草稿。
4. 生成包含 `Skill简介 / 使用场景 / 创作过程 / 使用步骤 / 效果展示 / Skill 链接 / 总结与思考` 的帖子。
5. 做一次发布前检查，提醒需要补截图、链接或脱敏的位置。

### 5、效果展示

准备展示的材料：

- 使用前：只有两个论坛链接和一个空的 `ai/Trae` 目录。
- 使用后：
  - `contest-analysis.md`：比赛规则和评分信号分析。
  - `project-options.md`：候选项目方向和取舍。
  - `recommended-plan.md`：推荐方案和执行路线。
  - `skill-draft/solo-project-publisher/`：可迭代的 Skill 草稿。
  - `forum-post-draft.md`：论坛参赛帖初稿。

### 7、总结与思考

后续我想把它扩展成几个更具体的发布模式：

- 工程功能发布模式：更关注需求、实现、测试和风险。
- 工具/脚本发布模式：更关注输入、输出、命令和复现。
- 比赛/活动投稿模式：自动检查活动要求是否都覆盖。

也欢迎大家提建议：你们在用 TRAE SOLO 做项目时，最希望它帮你整理哪类发布材料？
