# SOLO Project Publisher: Turn Real Repository Work Into A Publishable Project Post

## Skill Introduction

SOLO Project Publisher is a publishing assistant for developers. It turns real project evidence such as files, planning docs, command outputs, screenshots, and generated artifacts into a structured community post or project report.

## Use Scenario

After completing a feature, tool, or contest project, developers often need to explain the background, process, result, screenshots, and links. The source material is usually scattered across repositories, terminal output, documents, and screenshots. It is easy to miss evidence or accidentally expose sensitive information.

## Creation Process

The Skill turns publishing into a five-step workflow: scope, inspect, package evidence, draft, and pre-publish review. Two constraints drive the design: key claims should be evidence-backed, and public output must pass a safety review.

## Usage Steps

1. Provide the target project directory and publishing channel.
2. Define what can be public and what must be excluded.
3. Let the agent inspect public-safe materials and draft the post.
4. Review the missing-materials checklist.
5. Add screenshots, source links, and safety review notes before publishing.
